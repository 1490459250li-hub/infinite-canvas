# 无限画布 · 多模型

AI 修图用的无限画布：左侧多画布，中间画布节点（笔记 / 生成结果），底部一句话生成，
默认真实调用 `token.sensenova.cn`，密钥只留在本机。

**v3.3：这一轮全按你提的 10 条改。**

**① 窗口拖不动**：`ReleaseCapture` 以前只释放「调用线程」的捕获，而鼠标按下时捕获其实在
WebView2 的 Chromium 子窗口上，等于没释放 —— 系统的移动循环收不到 mousemove。现在先
`SetCapture(hwnd)` 把捕获抢回来再释放，同时给 `SendMessageW / SetCapture` 补了 64 位签名。

**①-b v3.5 又改了一次**：上面那招在真机上仍然不灵 —— `SetCapture` 在 js_api 的工作线程里调，
跨线程抢不到 Chromium 的捕获；系统移动循环收不到 mousemove，标题栏照样拖不动。现在改成
**按下后起一个 80fps 的线程读 `GetCursorPos`，用「光标位移 + 按下时的窗口位置」直接
`SetWindowPos`**，按键松开（`GetAsyncKeyState`）就退出。全程不碰鼠标捕获、不碰消息循环，
跨进程/跨线程都成立；另外应用自己的顶栏（品牌/标题那一行）也能拖，不用非去摸上面 32px 细栏。

**② 失败后换模型重试没反应**：`startJob` 只写了 `then(成功)`，`runRealJob` 一旦抛出未捕获异常
（存图超配额之类），`queue.active` 永远不回落，队列占满后再点生成毫无反应。现在并发槽用
`finally` 语义释放；重试还会带上原始参数（局部重绘的选区不再丢），并把模型换成卡片当前选中的那个。

**③ 生成记录**：图片工具条新增「记录」按钮（时钟图标），右侧滑出面板按版本列出每次的
**功能 / 模型 / 比例 / 分辨率 / 耗时 / 提示词**，提示词可一键复制。

**④ 任务栏图标白边**：`app.ico` 里那条 256px 画笔是 **RGB 三通道、没有 alpha**，四角是实白
`(255,255,255)`，缩到 32px 就是白方块。现在从四角 flood fill 挖掉外部白底、把透明区 RGB 刷成主色
（避免缩小后泛白），并补齐 256/128/64/48/32/24/16 七个尺寸。

**⑤ 反选失效**：旧实现把补集栅格化成 96px 横条、只留最大的 4 块，套索是不规则形状，合并出来就是
「一道一道的横条、大片区域没选上」。现在反选记成一条语义化选区「整张图 − 原选区」，重绘时整图重绘、
贴回前把原选区按真实形状盖回去（洞里的像素保证不动）；再按一次反选即取消。

**⑥ 涂抹分次叠加**：以前每落一笔就是一条独立选区，各自还标 `1 2 3`。现在多笔并进同一条涂抹选区
（`segs`），统一描边、不标序号，和 PS 快速蒙版/即梦涂抹的直觉一致。

**⑦ 清空 / 重置重复**：「清空」只清选区，「复位视图」只复位缩放与平移，职责分开。

**⑧ 失败卡片**：错误原文改成可滚动区（最大 100px、字号 10.5px、可选中复制），标题和「复制原因 /

```bash
.\dist\无限画布\无限画布.exe --self-test                   # 退出码 0 表示页面与接口都能起来
```

产物是 **`proto\dist\无限画布\`** 整个文件夹（exe 5 MB + `_internal\` 依赖，合计约 29 MB）：

```
dist\无限画布\
  无限画布.exe
  update.json          ← 从 proto\update.json 复制，缺了「检查更新」会装傻
  _internal\
    canvas.html        ← 490 KB
    art\               ← 23 张预览图
    python*.dll ...
```

**分发**：把 `proto\update.json` 复制到 `dist\无限画布\`（`/api/update/check` 只认 exe 同目录），再把整个文件夹压成 `无限画布-v3.7.6-win64.zip`。
**不要把 `.env` 打进 zip** —— 那是加密后的 API Key，随包外发等于给了别人。
> ⚠️ 若你把 `dist\无限画布\` 直接当绿色版双击运行，设置里填的 Key 就写在 exe 同目录的 `.env`，
> 而 COLLECT 重打包会删掉整个输出目录。**v3.7.6 起按用户要求「打包不要保留 key」**：重打包前把这份 `.env`
> **移到项目内非分发备份位**（`.key-backups\`），打完**不放回** exe 旁边，zip 也排除它；新包首次启动需重新填 Key。
> 若你希望换包后免填，自行把备份的 `.env` 拷回 exe 同目录即可 —— 但这属于本机行为，不进任何分发产物。
打包件验收：`python tests\probe_exe_v370.py`（版本号 / .env 404 / 内嵌页面 md5 / 清单 / 包内无 .env）。

**为什么不用 onefile**：onefile 每次启动都要把 14 MB 的 exe 解压到 `%TEMP%\_MEIxxxx`，
实测 1.2–4.2 s，是冷启动唯一的硬瓶颈。onedir 省掉这一步后「程序就绪」从 2.05 s 降到 **1.47 s**、
「窗口可见」从 2.50 s 降到 **1.85 s**。
代价是分发变成文件夹 —— **给人时整个文件夹压 zip**，不要把 exe 单独拎出来（拎出去就缺 `_internal`）。

**出安装包（可选）**：装好 [Inno Setup 6](https://jrsoftware.org/isdl.php) 后一条命令：

```bash
cd E:\无限画布
powershell -ExecutionPolicy Bypass -File installer\build-installer.ps1
# → proto\dist\installer\无限画布-Setup-<版本>.exe
```

脚本从 `server.py` 的 `APP_VERSION` 读版本号，所以不会和程序漂移。
两条硬规矩写在 `.iss` 里：**`Excludes: ".env"`**（那份文件存着加密后的 API Key，
打进安装包等于随包外发）和**卸载不碰用户数据**（画布在 WebView2 的 IndexedDB 里，与安装目录无关）。
`.iss` 必须存成 **UTF-8 with BOM**，否则 ISCC 按 ANSI 读会把中文读成乱码。
装到哪：普通权限下 `{autopf}` 解析成 `%LOCALAPPDATA%\Programs`（免 UAC），
以管理员运行时落到 `Program Files`。本机目前还没装 Inno Setup，脚本尚未实际编译过。

密钥保存在**运行目录**的 `.env`（目录不可写时自动退回 `%LOCALAPPDATA%\SenseNovaCanvas\.env`），
**以机器码加密落盘**（`SENSENOVA_API_KEY_ENC=`），换一台机器无法解密，本机迁移到别的目录也不受影响。

> 混淆版 `canvas.html` 是打包用的产物，日常开发改 `canvas.src.html`，别直接改混淆版。

> 重建前如果旧 exe 还在运行，先关掉它：Windows 上端口是独占的，新实例会自己换端口，
> 但你自己看到的窗口可能还是旧进程。

> `dist\.env` 是你本机的密钥副本（双击即用）。**要把文件夹发给别人，先删掉这个文件**，
> 旧版 onefile 的打包备份留在 `proto\无限画布-onefile.spec.bak`，要回到单文件分发时改名回
> `无限画布.spec` 重打包即可（冷启会退回 2 秒以上）；
> 对方首次运行点右上角齿轮填自己的密钥即可，密钥也会以机器码加密保存。

## 数据存放

- 画布内容（节点、图片、历史版本、视角）：IndexedDB（`sensenova-canvas/boards`，随 WebView2 profile 落盘）
- 相机位置：localStorage `snc.views.v1`（`{画布id: {x,y,k}}`，最多留 60 块）——
  平移/缩放只写这里，不再触发整块画布重存
- 规模提醒静音：localStorage `snc.scalehint.v1`（`{画布id: 1}`）—— 只对点过「不再提醒」的那张画布生效
- 大图分片：IndexedDB `sensenova-canvas/chunks`（v3 升级时自动建表，图片 dataUrl 外置为分片记录，旧整块数据仍可读）
- 技能：IndexedDB `sensenova-canvas/skills`；MCP 连接：`sensenova-canvas/mcps`（v2 升级时自动建表，旧数据不动）
- 密钥：`.env` 里的 `SENSENOVA_API_KEY_ENC`（机器码加密，见上）；旧明文 `SENSENOVA_API_KEY` 仍可读并会自动迁移
- EULA 同意状态：localStorage `snc.eula.v1`
- v2.4 结构化开关：`snc.struct.all`（1 = 所有生成都包装，默认关）、`snc.struct.fmt`（text / json，默认 text）；
  参数浮层的选择只存在内存 `state.structParams`，刷新即清空，不落盘
- v2.5 优化器开关：`snc.struct.opt`（空 / t2i / i2i / multi，默认空 = 不注入模板）
- v2.6 分类模板开关：`snc.struct.cat`（空 = 不注入，否则注入 8 类自撰模板之一）
- 导出：默认弹系统「另存为」窗口（`POST /api/save-file`），写盘路径由用户选；

- 更新清单：`proto\update.json`（随 exe 同目录分发，`latest` + `notes` + `url`）

226. **整板导出会静默产出全黑图**（真 bug，本批最值得说的一个）。原代码：
    ```js
    var scale = Math.min(2, 2600 / bw);
    scale = Math.max(0.6, scale);      // ← 下限赢
    ```
    第一句说"宽度不超过 2600"，第二句又给 0.6 下限。`bw > 4333` 时下限赢，成品宽度
    = `bw × 0.6`；浏览器 canvas 单边上限约 16384，超了**不报错、不抛异常，直接给一张空白图**。
    高度更是完全没管 —— 一张 400×40000 的纵向长图，`want = min(2, 2600/400) = 2`，成品高 **80112**。
    修法：保留 0.6 作为起点，只在真会超限时用迭代收敛压回安全区。
    ```js
    var scale = Math.max(0.6, want);
    for(var gi = 0; gi < 8; gi++){
      var cw = bw*scale + pad*2, ch = bh*scale + pad*2;
      if(安全) break;
      var f = Math.min(16000/cw, 16000/ch, Math.sqrt(1.5e8/(cw*ch)));
      if(f >= 1) break;
      scale = Math.max(0.01, scale * f * 0.998);
    }
    ```
    必须按"成品尺寸"迭代而不是反解 `16000/(bw+pad*2)`：`pad` 是固定像素、不跟 scale 缩，
    反解会漏掉那一截，4 万高的图算出来 16067 还是超（第一版就是这么错的）。
    实测：400×40000 从 `912×80112` → `271×15969`，30300×300 从 `18292` → `15982`，
    而普通画布 `1952×712` 和 2 万见方 `12112×12112` **一个像素都没变**。
    `_clamped` 的判据是 `scale < 0.6` 而不是 `scale < want`：2 万见方的 `want` 只有 0.13，
    实际给了 0.6，跟以前观感一致，不该弹"已缩放"。

## 已知限制

- 局部重绘是"裁切 + 回贴"，接缝处偶有轻微透视不连续；不是蒙版级 inpainting（接口不支持）
- 参考图权重只能写进提示词（"弱/中/强"），接口没有数值权重字段
- 便签仍只读；没有分组、对齐吸附、命令面板（P1 方向）
- 历史版本存 IndexedDB，5 版/卡片；**历史版按 1024 长边存 JPEG**，当前版保留原始图。
  切到被压的历史版会提示「需要原尺寸请重新生成」——这是有意的取舍，历史版是回看用的
- MCP 只做了配置登记与校验，没有本地运行时，所以现在不会真的调用工具（入口已留）
- 8K 是本地插值，像素数够但不会凭空多出细节；模型的真实上限是单边 4096
- SenseNova 没有扩图（outpaint）接口：`/images/outpaint`、`/images/expand`、`/images/upscale` 都是 404
- 技能是提示词片段，不是能执行代码的插件；导入的 SKILL.md 只取正文当提示词用
- 主题只换配色，不改布局：亮色下画布点阵会比暗色更淡，这是刻意的（点太深会抢图片视觉）
- 预览图走本地 `/art/` 外链，不在 `canvas.html` 里，所以**不能只把 canvas.html 拷给别人跑**
  （要用就得连 art 目录一起；打包件已经把 art 打进 `_internal\art\`，不受影响）
- JS 混淆是「打散变量名 + 压缩」，非运行时加密：能防随手复制，但挡不住下定决心的逆向（EULA 已从
  法律层面声明禁止）；Python 侧保护（Cython / PyArmor）留到下一轮
- 打包是 onedir，分发是一个约 28 MB 的文件夹；只把 exe 拷出去会因缺 `_internal` 起不来
- 密钥加密用的是机器码绑定：换机器 / 换用户名 / 换 CPU 后需重填密钥；同一台机器重装系统也可能失效
- P0 缩略图只作用于有 `dataUrl` 的生成/导入大图；内置示例照片（走 `photo` 字段）本身已压缩、不再二次压。
  双击放大预览永远读原图（`n.dataUrl`），不受缩略图影响
